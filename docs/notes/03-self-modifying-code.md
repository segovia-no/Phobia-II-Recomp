# 03 — The self-modifying mixer

The music/effects software mixer (Impulse Tracker player) has 19 inner-loop routines at `0x447210–0x448915` (8/16-bit, mono/stereo, interpolation variants). A table in DGROUP at `0x4511c8` holds `(start, end)` pairs. At run time the player:
1. copies a routine into the heap,
2. patches it: placeholders `0xBABEFACE` / `0xACDCABBA` (fixed-point step), zero displacements (volume table base), and a `jmp +0` rel8 that selects the entry point into the unrolled loop,
3. calls the heap copy through a function pointer.

A static translation of the original bytes would mix with the placeholders. The recompiler instead lifts these routines in **SMC mode**:
- every immediate, displacement and branch offset is read at run time from the *live* instruction bytes (`RD32(insn_addr + field_offset + D)`), where `D` is the distance between the executing copy and the original;
- relative branches compute their target at run time and `switch` over every instruction in the routine (with a fast path for the unpatched target);
- the opcode structure is assumed fixed (only operand fields change) — true for this mixer.

The dispatcher recognises a heap address as a copy by comparing it with each routine's *fixed* bytes (a mask generated by the recompiler excludes immediate/displacement fields), caches the match, sets `c->smc_delta` and calls the compiled routine. Patches to the original in place (`D = 0`) work the same way.
